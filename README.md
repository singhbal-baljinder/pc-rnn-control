# Online Predictive Coding for Adaptive Shape Control of Soft Robots

Code and data for the paper's two experiments on a cable-driven soft arm
(`docs/paper.pdf`):

- **Open loop** — a multi-seed one-step forward-prediction sweep that ranks the
  predictors (PC-RNN-I at *N* ∈ {1,2,5,10}, CerebNet, LWPR, LoG-GP and nine
  online-RNN learning algorithms) over 5 test trajectories and 5 seeds.
- **Closed loop** — the same predictors placed inside the controller and run on
  the physical robot, at 10 Hz and 20 Hz, in a nominal and a frozen-actuator
  condition.

Every number in the paper comes from the physical robot; there is no simulation
experiment. This is the code that produced those results — reorganised into one
library and renamed for legibility, with the logic untouched. See
[Deviations](#deviations) for the four behavioural changes and why.

## Layout

```
src/pc_rnn_control/
  robot/      motors.py  frames.py  policy.py  control_thread.py
  methods/    online_learning.py    the interface: any method by name
              predictive_coding.py  PC-RNN-I
              cerebnet.py           the CerebNet baseline
              dataset.py  normalization.py
              rnn/        the nine online RNN algorithms
              gp/         LoG-GP
  mocap/      OptiTrack streaming (robot runs only)
scripts/      run_babbling.py  train_policy.py  run_closed_loop.py
              run_openloop_sweep.py  make_figures.py
third_party/  lwpr/       the LWPR baseline, C sources (LGPL)
data/         the recorded runs (see Data)
docs/         the paper
```

## Install

Two ways. **pixi** gives you the whole environment including the C toolchain
the LWPR baseline needs, pinned by `pixi.lock`:

```bash
pixi install
```

Or pip, if you do not need LWPR:

```bash
python -m venv .venv && . .venv/bin/activate
pip install -e .            # figures + open-loop study
pip install -e ".[robot]"   # additionally: motors and motion capture
```

Python 3.11–3.14. Nothing is compiled; `scipy<2` is pinned because the RNN
algorithms use `scipy.ndimage.filters`, removed in SciPy 2.

### The LWPR baseline

LWPR is a C library, so it has to be compiled. It is bundled at
`third_party/lwpr/` (LGPL-2.1, see `NOTICE`) and pixi provides the toolchain:

```bash
pixi install
pixi run build-lwpr
```

Or by hand, into whatever environment you are using:

```bash
cd third_party/lwpr && mkdir -p build && cd build
cmake .. -DCMAKE_INSTALL_PREFIX=$CONDA_PREFIX -DNUM_THREADS=1 && make && make install
python -c "import pylwpr"
```

The install prefix matters — the extension links against `liblwpr.so.1`, which
has to land somewhere the loader will find it. Keep `NUM_THREADS=1`: more than
one thread changes the order of floating-point summation, and the paper's
numbers come from the single-threaded build. Note `pip show pylwpr` will never
find it; it is a `make install` drop, not a pip package.

Building it is optional. Without it the LWPR baseline is skipped and every other
method runs normally.

## Reproducing the figures and tables

```bash
python scripts/make_figures.py
```

About a minute from the shipped cache. Figures land in the working directory,
the `.tex` table fragments in `tables/`.

| Paper float | File | Generated by |
|---|---|---|
| Fig. 3 | `F_closed_loop_2x2.pdf` | `fig_closed_loop_grid` |
| Fig. 4 | `F_tracking_timeseries_v21_10Hz.pdf` | `fig_actuation_tracking_grid` |
| Table I | `ranking_table.tex` | `make_ranking_table` |
| Table II | `tables/openloop_full_table.tex` | `make_openloop_full_table` |
| Table III | `tables/open_closed_table.tex` | `make_open_closed_table` |
| Table IV | `timing_table.tex` | `make_timing_table` |

Every [GitHub release](https://github.com/singhbal-baljinder/pc-rnn-control/releases)
attaches these six files, regenerated from the tagged commit by
`.github/workflows/release.yml`, so you can check them against the paper without
installing anything.

Closed-loop metrics come from a precomputed DataFrame, `data/closed_loop_cache.pkl`.
**Delete it to recompute everything from the raw recordings** — the `.npz` and
the policy checkpoint are all here, so the cache is a convenience, not a
dependency:

```bash
rm data/closed_loop_cache.pkl && python scripts/make_figures.py
```

## Re-running the open-loop study

```bash
python scripts/run_openloop_sweep.py
```

Sweeps every method over 5 seeds on each of the 5 trajectories and writes one
pickle per recording to `data/open_loop/`, which is
what Table III reads. No hardware needed. Configuration is the block at the top
of the file: `SEEDS`, `BASE_METHODS`, `N_SWEEP`. Runtime is hours, dominated by
the RNN algorithms; the shipped pickles are the outputs of exactly this script.

## Re-running the closed-loop robot experiment

Needs the hardware: three Dynamixel motors on a serial bus (`/dev/ttyUSB0`) and
an OptiTrack system streaming over NatNet. Set the mocap addresses for your
network near the top of the runner (`optionsDict["serverAddress"]` /
`["clientAddress"]`); the shipped values are the link-local addresses of the
direct connection used here.

```bash
python scripts/run_babbling.py       # 1. collect data
python scripts/train_policy.py       # 2. train the fixed policy
python scripts/run_closed_loop.py    # 3. one run
```

Step 3 performs **one** run: one method, one trajectory, one rate, one
condition. The 20 blocks per method in the paper are 20 invocations. It is
configured by editing the globals near the top of the file — that is how the
reported runs were produced, and it is kept rather than wrapped in a CLI so the
shipped file matches what was executed:

| Global | Values | Meaning |
|---|---|---|
| `version` | `5, 19, 21, 23, 35` | test trajectory |
| `desired_freq` | `[10]`, `[20]` | control rate of this run |
| `condition` | `""`, `"_fault"` | nominal, or motor 0 frozen |
| `USE_ADAPTIVE_MODEL` | `True` / `False` | a learner, or a baseline |
| `ADAPTIVE_METHOD` | `temporal_pc`, `cerebnet`, `log_gp`, `lwpr`, `rnn-uoro` | which learner |
| `idx_trial` | `0, 20, 40, 60` | trial index — **for PC-RNN-I this selects *N*** (below) |
| `TEST_CLOSED_LOOP_WITHOUT_ADAPTATION` | `True` / `False` | when `USE_ADAPTIVE_MODEL=False`: NCL-C, or OL-C |

The fault is a frozen motor 0 between samples 400 and 900 (`TIME_INTERVAL_BLOCKS`).

## Data

`data/closed_loop/` — 210 closed-loop recordings, the
fixed policy `lstm_inverse_dynamics.pth`, and the babbling set it was trained
on. Filenames follow

```
spiraling_babbling_{10|20}_Hz_test_trajectory_{v5|v19|v21|v23|v35}_mvel0.5[_suffix][_fault].npz
    <no suffix>                    the reference trajectory
    _closed_loop_seq0              NCL-C  (fixed policy, no online learning)
    _open_loop_seq0                OL-C   (no feedback)
    _seq{cerebnet|log_gp|lwpr|rnn-uoro}_adaptive0
    _seqtemporal_pc_adaptive{0|20|40|60}
```

**PC-RNN-I's *N* is encoded in the trial index, not the filename:**
`0 → N=2`, `20 → N=5`, `40 → N=1`, `60 → N=10`.

Each recording holds the executed motor commands, the 8×3 marker positions and
quaternions, the forward-model predictions and per-step timings. Positions are
transformed into the arm's base frame and converted to millimetres before any
metric is computed; the four observed backbone frames are indices 1, 3, 5, 7,
the last being the tip.

`data/open_loop/` — the 5 source recordings and the
5 multi-seed result pickles behind Table III. Only the 10 Hz half ships: the
loader keeps one recording per trajectory, and the 10 and 20 Hz source files are
identical for three of the five.

## Deviations

The code was **repackaged**: files renamed for what they do, gathered into one
`pc_rnn_control` library, and every import updated to match. No logic changed.

Four behavioural changes, all to make the release runnable and portable:

1. **The fault is now gated on the condition.** In the runner as used, the
   motor-freeze block executed unconditionally and `condition` only renamed the
   output file; the nominal runs were produced with that block disabled by hand.
   It is now `if condition` — so both conditions reproduce from one file.
2. **A missing `pylwpr` disables only LWPR.** It previously raised at import
   time and took every other method down with it.
3. **Two absolute paths** in `methods/signal_utils.py` default arguments became
   `None`. They pointed at a directory unrelated to these experiments.
4. **Data paths** in the scripts follow the new one-level layout (`../data`).
5. **Code not used by any reported result was removed.** The library ships the
   methods the paper runs and the paths that produce its numbers; dispatch
   branches, helpers and diagnostics that no reported result executes were
   dropped. Verified rather than assumed: re-running the open-loop sweep after
   the removals reproduces the mean RMSE of all 19 methods exactly, and the
   three result tables still match the paper digit for digit.

Nothing that touches a reported number was modified.
